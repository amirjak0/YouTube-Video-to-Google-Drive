# YouTube Video to Google Drive

انتقال و همگام‌سازی ویدیوهای یک پلی‌لیست یا لینک تکی YouTube با یک پوشه در Google Drive، با استفاده از Python، `yt-dlp` و GitHub Actions.

> **وضعیت فعلی پروژه:** مسیر عملیاتی دانلود و آپلود خودکار، فایل `main.py` است که از طریق GitHub Actions اجرا می‌شود. داشبورد وب موجود در `src/` و `server.ts` در حال حاضر یک نمونهٔ نمایشی (Demo) با داده‌ها و عملیات شبیه‌سازی‌شده است و به موتور واقعی پایتون یا API واقعی Google Drive متصل نیست. جزئیات این تفاوت در بخش «داشبورد وب» آمده است.

## قابلیت‌های موتور اصلی (Python)

- دریافت ویدیو از یک YouTube Playlist یا یک لینک ویدیوی تکی.
- بررسی فرمت‌های قابل دریافت با چند YouTube player client و انتخاب بالاترین وضوح قابل دسترس، با رعایت سقف کیفیت تعیین‌شده.
- دریافت فرمت‌های ویدیویی و صوتی با `yt-dlp`؛ هنگام نیاز به ادغام جریان‌های جداگانه، FFmpeg آن‌ها را در قالب MKV ترکیب می‌کند. اگر YouTube یک فرمت ترکیبی آماده ارائه کند، پسوند فایل می‌تواند تابع فرمت منبع باشد.
- استفاده از کوکی اختیاری YouTube که از متغیر محیطی یا GitHub Secret دریافت می‌شود.
- بررسی فایل‌های موجود در پوشهٔ مقصد Google Drive و شناسایی ویدیو با شناسهٔ ۱۱ کاراکتری داخل نام فایل.
- رد کردن دانلود مجدد وقتی نسخهٔ موجود در Drive از وضوح قابل‌دسترس فعلی کمتر نیست.
- در صورت فعال بودن ارتقای خودکار، دریافت نسخهٔ باکیفیت‌تر، آپلود نسخهٔ جدید و سپس تلاش برای حذف نسخهٔ قدیمی‌تر.
- پردازش هم‌زمان حداکثر ۳ ویدیو.
- حذف فایل موقت دانلودشده از runner پس از پایان موفق پردازش هر ویدیو.

نام فایل‌های خروجی به این الگو ساخته می‌شود:

```text
Video Title [YOUTUBE_VIDEO_ID] [1080p].mkv
```

شناسه و وضوح داخل نام فایل برای پیدا کردن و مقایسهٔ نسخه‌های قبلی در Google Drive استفاده می‌شوند؛ بنابراین بهتر است این الگوی نام‌گذاری حفظ شود.

## اجرای خودکار با GitHub Actions

Workflow اصلی در این مسیر قرار دارد:

`/.github/workflows/run.yml`

### زمان‌بندی

- اجرای خودکار طبق Cron در دقیقهٔ صفر، هر ۶ ساعت یک‌بار (زمان‌بندی Cron در GitHub بر اساس UTC است).
- امکان اجرای دستی از مسیر **GitHub → Actions → YouTube to Google Drive → Run workflow**.
- پس از اجرای دانلودر، مرحلهٔ نگهداری تاریخچه تلاش می‌کند فقط ۵ اجرای جدید همین Workflow را نگه دارد و اجراهای قدیمی‌تر را حذف کند. این پاک‌سازی به مجوز `actions: write` نیاز دارد و با `if: always()` حتی در صورت شکست مرحلهٔ دانلودر نیز اجرا می‌شود.

### ورودی‌های اجرای دستی

| ورودی | مقدار پیش‌فرض | توضیح |
|---|---:|---|
| `update_existing` | `true` | اجازه می‌دهد ویدیوی موجود، در صورت در دسترس بودن نسخه‌ای با وضوح بالاتر، ارتقا پیدا کند. |
| `force_quality` | `2160` | سقف وضوح دانلود بر حسب عدد؛ برای مثال 2160، 1440، 1080 یا 720. |

در اجرای زمان‌بندی‌شده نیز Workflow مقدار پیش‌فرض `true` برای ارتقای خودکار و `2160` برای سقف کیفیت را استفاده می‌کند.

## راه‌اندازی و تنظیم Secrets

برای اجرای واقعی در GitHub، از صفحهٔ مخزن به مسیر زیر بروید:

**Settings → Secrets and variables → Actions → New repository secret**

این مقادیر را به‌عنوان Repository Secret اضافه کنید:

| نام Secret | ضروری؟ | کاربرد |
|---|---|---|
| `YOUTUBE_PLAYLIST_URL` | بله، یا جایگزین آن | آدرس پلی‌لیست یا ویدیوی YouTube که قرار است پردازش شود. |
| `GDRIVE_CLIENT_ID` | بله | شناسهٔ OAuth Client گوگل. |
| `GDRIVE_CLIENT_SECRET` | بله | رمز OAuth Client گوگل. |
| `GDRIVE_REFRESH_TOKEN` | بله | Refresh Token برای دسترسی به Google Drive. |
| `GDRIVE_FOLDER_ID` | بله | شناسهٔ پوشهٔ مقصد در Google Drive. |
| `YOUTUBE_COOKIES` | اختیاری | محتوای کامل فایل کوکی با فرمت Netscape؛ برای حساب یا ویدیوهایی که به کوکی نیاز دارند. |

کد پایتون، آدرس ورودی را ابتدا از `YOUTUBE_PLAYLIST_URL` می‌خواند و اگر تنظیم نشده باشد از `YOUTUBE_VIDEO_URL` استفاده می‌کند. در Workflow فعلی GitHub Actions، Secret با نام `YOUTUBE_PLAYLIST_URL` به برنامه پاس داده می‌شود؛ بنابراین برای اجرای خودکار مخزن همین Secret را تنظیم کنید. `YOUTUBE_VIDEO_URL` جایگزین قابل استفاده برای اجرای مستقیم محلی است.

**نکات امنیتی:**
- مقدار کوکی را در Secret با نام `YOUTUBE_COOKIES` قرار دهید؛ فایل کوکی را به مخزن GitHub Commit نکنید.
- فایل کوکی باید محتوای متنی معتبر Netscape داشته باشد. برنامه آن را هنگام اجرا در فایل موقت می‌نویسد و در پایان حذف می‌کند.
- Client Secret، Refresh Token و کوکی‌ها را عمومی نکنید و داخل کد یا README قرار ندهید.
- برای دسترسی Google Drive باید OAuth Client و Refresh Token معتبر داشته باشید و حساب گوگل به پوشهٔ مقصد دسترسی لازم را داشته باشد.

## متغیرهای محیطی

موتور پایتون این متغیرها را می‌شناسد:

| متغیر | پیش‌فرض / جایگزین | توضیح |
|---|---|---|
| `YOUTUBE_PLAYLIST_URL` | جایگزین: `YOUTUBE_VIDEO_URL` | آدرس پلی‌لیست یا ویدیوی YouTube. |
| `YOUTUBE_VIDEO_URL` | خالی | جایگزین آدرس ورودی، اگر `YOUTUBE_PLAYLIST_URL` تنظیم نشده باشد. |
| `YOUTUBE_COOKIES` | خالی | محتوای فایل کوکی Netscape؛ اختیاری. |
| `GDRIVE_CLIENT_ID` | خالی | OAuth Client ID. |
| `GDRIVE_CLIENT_SECRET` | خالی | OAuth Client Secret. |
| `GDRIVE_REFRESH_TOKEN` | خالی | Google OAuth Refresh Token. |
| `GDRIVE_FOLDER_ID` | خالی | شناسهٔ پوشهٔ مقصد در Drive. |
| `UPDATE_EXISTING` | `true` | فعال یا غیرفعال کردن ارتقای فایل‌های موجود. |
| `FORCE_QUALITY_LIMIT` | `2160` | حداکثر ارتفاع تصویر موردنظر، بر حسب پیکسل. |

برای اتصال واقعی به Google Drive، هر سه مقدار `GDRIVE_CLIENT_ID`، `GDRIVE_CLIENT_SECRET` و `GDRIVE_REFRESH_TOKEN` باید تنظیم باشند. در غیر این صورت، سرویس Drive ساخته نمی‌شود و آپلود واقعی انجام نخواهد شد. توجه کنید که در کد فعلی، حالت بدون اعتبارنامه فقط پیام local mode ثبت می‌کند و نتیجهٔ آن در فراخواننده موفق تلقی می‌شود؛ سپس فایل موقت دانلودشده حذف می‌شود. بنابراین این حالت آرشیو محلی ماندگار ایجاد نمی‌کند و برای استفادهٔ واقعی حتماً اعتبارنامه‌های Drive را تنظیم کنید.

### رفتار ارتقای ویدیوهای موجود

- اگر ویدیو در Drive پیدا نشود، دانلود و آپلود می‌شود.
- اگر وضوح فایل موجود برابر یا بیشتر از بالاترین وضوح شناسایی‌شده در YouTube باشد، برنامه از آن عبور می‌کند.
- اگر فایل موجود کیفیت پایین‌تری داشته باشد و `UPDATE_EXISTING=true` باشد، برنامه نسخهٔ جدید را دریافت می‌کند.
- فایل قدیمی فقط پس از آپلود موفق نسخهٔ جدید برای حذف فرستاده می‌شود. اگر حذف فایل قدیمی ناموفق باشد، هشدار ثبت می‌شود.
- با `UPDATE_EXISTING=false`، ویدیویی که از قبل در Drive وجود دارد ارتقا داده نمی‌شود؛ ویدیوهای جدید همچنان قابل انتقال هستند.

## اجرای محلی موتور پایتون

نیازمندی‌ها:
- Python 3.11 یا نسخهٔ سازگار.
- FFmpeg و ابزار `ffprobe` (معمولاً همراه FFmpeg نصب می‌شوند).
- دسترسی معتبر به Google Drive API برای آپلود واقعی.
- پکیج‌های فهرست‌شده در `requirements.txt`.

نصب وابستگی‌های Python:

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

مقادیر محیطی موردنیاز را در سیستم خود تنظیم کنید و سپس اجرا کنید:

```bash
python main.py
```

فایل `.env.example` صرفاً نمونهٔ نام و شکل متغیرهاست؛ `main.py` به‌تنهایی فایل `.env` را بارگذاری نمی‌کند. در اجرای محلی، متغیرها باید در محیط Shell یا ابزار اجرا تنظیم شوند.

## داشبورد وب (React / Express)

پروژه یک رابط وب نیز دارد که با React، Vite و Express ساخته شده است. اسکریپت‌های تعریف‌شده در `package.json`:

| دستور | کاربرد |
|---|---|
| `npm run dev` | اجرای سرور توسعه از طریق `tsx server.ts`. |
| `npm run build` | اجرای TypeScript build و ساخت خروجی Vite. |
| `npm run preview` | پیش‌نمایش خروجی Vite. |
| `npm run lint` | بررسی TypeScript با `tsc --noEmit`. |

برای نصب پکیج‌های Node.js و اجرای داشبورد نمایشی (به‌صورت پیش‌فرض روی پورت 3000؛ قابل تغییر با متغیر محیطی `PORT`):

```bash
npm install
npm run dev
```

**محدودیت مهم داشبورد فعلی:** فایل `server.ts` از فهرست نمونهٔ ثابت و داده‌های حافظه‌ای استفاده می‌کند. عملیات Scan، Probe، Sync، حذف فایل و گزارش‌های این داشبورد شبیه‌سازی شده‌اند؛ این سرور در نسخهٔ فعلی نه `main.py` را اجرا می‌کند و نه عملیات واقعی را از طریق Google Drive API انجام می‌دهد. تنظیمات داشبورد نیز در حافظه نگهداری می‌شوند و با راه‌اندازی مجدد سرور از بین می‌روند. زمان‌بندی واقعی شش‌ساعته متعلق به GitHub Actions است، نه زمان‌بند داخل داشبورد.

همچنین فایل `.env.example` به‌تنهایی توسط `server.ts` بارگذاری نمی‌شود؛ متغیرهای محیطی باید توسط محیط اجرا در اختیار Node.js قرار بگیرند.

## ساختار مهم مخزن

```text
.
├── .github/
│   └── workflows/
│       └── run.yml       # زمان‌بندی و اجرای GitHub Actions
├── main.py               # موتور واقعی دانلود و همگام‌سازی Python
├── requirements.txt      # وابستگی‌های Python
├── .env.example          # نمونهٔ متغیرهای محیطی
├── server.ts              # سرور نمایشی Express و APIهای شبیه‌سازی‌شده
├── src/                   # رابط کاربری React
├── index.html
└── package.json           # اسکریپت‌ها و وابستگی‌های Node.js
```

## عیب‌یابی

**هیچ فایلی در Google Drive آپلود نمی‌شود**
- نام Secretها را دقیقاً مطابق جدول بررسی کنید.
- معتبر بودن OAuth Client ID، Client Secret و Refresh Token را بررسی کنید.
- مطمئن شوید `GDRIVE_FOLDER_ID` مربوط به پوشهٔ صحیح است و حساب OAuth به آن دسترسی دارد.

**دانلود YouTube با خطا مواجه می‌شود**
- ممکن است ویدیو خصوصی، محدود به سن/منطقه، حذف‌شده یا نیازمند ورود باشد.
- در صورت نیاز، محتوای تازهٔ کوکی را در `YOUTUBE_COOKIES` قرار دهید.
- خطاهای فرمت را از بخش Logs همان اجرای GitHub Actions بررسی کنید؛ در دسترس بودن کیفیت به فرمت‌هایی که YouTube برای آن ویدیو ارائه می‌کند بستگی دارد.

**نسخهٔ جدید جایگزین نسخهٔ قبلی نمی‌شود**
- مقدار `update_existing` را در اجرای دستی روی `true` بگذارید.
- برنامه شناسهٔ ویدیو و وضوح را از نام فایل موجود در Drive تشخیص می‌دهد؛ الگوی `[VIDEO_ID] [1080p]` باید حفظ شده باشد.

**اجراهای قدیمی GitHub Actions حذف نمی‌شوند**
- مرحلهٔ `Keep only the latest 5 workflow runs` را در لاگ اجرا باز کنید.
- این مرحله از GitHub CLI و `jq` استفاده می‌کند؛ در صورت خطا، خروجی همان مرحله علت دقیق را نشان می‌دهد.
- مجوز `actions: write` در بخش `permissions` فایل Workflow باید فعال باشد.
